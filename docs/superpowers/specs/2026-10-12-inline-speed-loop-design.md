# inline AI 처리 시간 개선 루프 — 설계

2026-10-12 · 기준: 사이트(myfirstaigent) 실습 01~09 · 기준 PC: 강사 PC

## 목표
inline AI(낮은 모델)가 사이트 프롬프트로 실습을 **한 프롬프트당 3분 이내**에 끝내고, 결과물이 정답 수준이 되게 한다.
모델은 못 바꾸므로 바꿀 수 있는 것(실습 자료 · 프롬프트 · 작업 단위)만 고친다.
업무지침은 이미 가볍게 줄였으므로(짧은판 854B) 이번 루프의 주 대상이 아니다.

## 결정 사항
- 실제로 inline AI에 보내 측정한다(크레딧 소모 승인, 10/12).
- 사이트가 기준. 실습 자료 원본 = `download/inlineAI_실습.zip`, 프롬프트 원본 = 각 폴더 `프롬프트.txt`(09는 `시작_프롬프트.txt`).
- 실습 자료 속 이름·전화는 모두 가상(점검 대상 아님).
- 앱 로그는 `LOGENC` 암호화 → 측정은 UIA 화면 관찰로만.

## 구성
`tools/speedloop/`
- `cases.yaml` — 프롬프트 1개 = 케이스 1개. 열 파일, 폴더 첨부 여부, 프롬프트 출처, 자동 답변, 채점 규칙.
- `reset.py` — 바탕화면 `inlineAI_실습`을 처음 한 번 백업하고, 매 회 zip 기준 상태로 되돌린다(앱에 등록된 폴더 경로는 그대로).
- `run_case.py` — pywinauto UIA: 새 에이전트 → 파일 열기(한글·엑셀·PPT, `os.startfile`) / 폴더·파일 첨부 → 프롬프트 붙여 넣기 → 전송.
  2초마다 상태(응답 중/대기) 확인, 15초마다 PrintWindow 캡처, 채팅 텍스트 UIA로 저장.
  AI가 되물으면 `cases.yaml`의 답을 보냄(최대 2회). 10분 넘으면 중단.
- `grade.py` — 새 파일 생성 여부·행 수·필수 문구 등 케이스별 확인.
- `runs/<case>/<회차>/` — 캡처·채팅 텍스트·`result.json`. 전체 기록은 `results.jsonl`.

## 루프
1. 케이스 실행 → 시간·되묻기 횟수·채점 기록
2. 캡처와 채팅 기록에서 가장 오래 걸린 구간 하나를 찾음
3. 원인 하나만 고치고 다시 실행
4. 3분 이내 + 채점 통과면 다음 케이스, 아니면 케이스당 최대 4회

### 고치는 순서
1. **자료 줄이기** — 큰 PDF는 필요한 쪽만 또는 텍스트 md로(09 `science_5-2-4.pdf` 37MB, 05 회계 지침 PDF 2.8MB, 00 공문서 규정 PDF), 판단에 안 쓰는 파일 정리
2. **프롬프트 닫기** — 파일 이름 정확히, 저장 이름 지정, 선택지·되묻기 조건은 꼭 필요한 곳만
3. **쪼개기(정 안 되면)** — 한 프롬프트에 일이 여러 개면 순서대로 나눈 프롬프트로. 사이트에는 ①②로 이어서 보내게 표시
   - 후보: 01-3(중복 삭제 + 분류), 02-1(통신문 + 활동지), 06-1(계획 업데이트 + 공문), 06-2(이미지 추출 + 검색 + 배정 + 예산), 04-3(두 계획 읽기 + 회의록)
4. **양식 미리 채우기** — AI 할 일을 줄이는 준비(예: 블루킷 머리행)

## 먼저 할 일(스파이크, 1회 실행)
01-1로 확인: ① 응답 중/완료 상태를 UIA로 판별 가능한가 ② 폴더 첨부 자동화 가능한가.
안 되는 부분은 반자동(첨부만 사람이, 측정은 자동)으로 바꾼다.

## 예산·안전
- 전체 최대 약 40회 전송. 넘을 것 같으면 멈추고 묻는다.
- 루프 중에는 inline AI·한글 창을 건드리지 않는다(화면 자동 조작).
- 실습 자료·프롬프트 수정은 레포에서 하고 zip을 다시 만든다. push(배포)는 선생님 확인 후.
